# Consent Gap Lab

Decision, 2026-09-30: build a zero-wallet educational probe of crypto consent gaps. A visitor sees the same fictional “Approve 20 TEST” button under two different simulated permissions, predicts whether the approval could cover more than 20 TEST, and receives an explicit comparison and shareable result URL. A real wallet is never requested. A person learning approvals can finish in under 90 seconds.

The useful mechanism is comparison of button language to permission scope, not autonomous testing in general. The connected portable Flow now reads an owned synthetic JSON specimen over HTTP, validates its schema and expected permission, and returns a timestamped verdict and payload digest. This is an owner-controlled orchestration spike, not browser automation. **Two distinct owner-run inputs have succeeded with verified outputs at revision `d85a1ddc7bb9cd1cc6a13b4d5db95474228f1fe9`, observed on 2026-10-06.** Read `/evidence.html` for actual timestamps, deliberately redacted outputs and exact source links. This proves that historical HTTP JSON observation, not every current application behavior. UiPath provides the independent, revision-bound observation path; the public teaching interaction does not depend on Cloud availability. Later work can add opt-in UI journeys without misrepresenting this JSON spike as a wallet test.

Rejected for now: generic crypto browser journey runner (Synpress and Well Tested already cover much of testing and evidence); autonomous bug-fixing agent (Gauntlet, SpectreAI and FlakeWarden cover adjacent terrain, with too much uncontrolled surface); agent-verification scoreboard (AgentTrial already publishes sealed trials and receipts). The selected consent-specific question has a clearer public interaction and lower risk. At selection the UiPath component still needed a real spike; the later two-input HTTP JSON proof meets that narrow requirement, not a browser-journey claim.

Scope: synthetic teaching fixtures and optional visitor-pasted calldata decoded entirely in the browser; no account credentials, transactions or visitor-triggered Cloud runs. The optional 2026-10-07 button-amount field compares a visitor's unverified amount to the decoded request with exact integer differences; it does not authenticate button text, infer decimals or declare a match safe. The 2026-10-06 local inspector extends the lesson to a visitor's own request without turning it into a wallet audit. It only decodes the canonical ERC-20 approval layout, shows exact raw units plus explicitly supplied decimals, and refuses unsupported layouts. Standard ABI decoding is established functionality, not our novelty claim. This gives the comparison an immediate practical follow-through; the separately published UiPath proof is limited to the earlier owned JSON observations. No pasted bytes are uploaded, stored by the app or put into result URLs. Suggested cases via GitHub issues are editorial feedback, never a work queue. No UiPath endorsement. No guarantee a simulated finding reflects real application behavior. If a real run is later published, show timestamp, source revision, redaction method and uncertainty; do not publish raw tenant traces. Revisit the concept if real visitors do not find the comparison useful.
