# Design notes

Audience: a wallet user asked to approve a token, plus a UiPath builder inspecting a reproducible test fixture. Hero sets the question; neutral specimen A/B buttons switch between fictional approvals without revealing scope before the prediction; the visitor commits a prediction, reads scope and caveat, then copies a URL carrying case and answer. There is no wallet connect or submit-to-server path. Selection and reveal remain usable without Cloud runs.

Visual vocabulary: dark laboratory, acid-green cues, high-contrast specimen panels. Accessible button controls, announced result, responsive single-column mobile layout. No pictorial claim of an actual wallet screenshot. Static Node server serves only local files; CSP restricts resources. /healthz is the deployment readiness check, not a proof of journey functionality.

The optional comparison mode (`?view=compare#comparison`) is reachable before or after a prediction. It derives both cards from the existing local specimens, highlights allowance differences, shows the common button and separate approval action, and offers a shareable URL. Desktop cards are adjacent; mobile cards stack. The comparison heading receives keyboard focus, and returning to a fresh prediction resets spoilers and restores focus. Copy failure preserves the address-bar link. No visitor action starts a job. A correct guess is labelled as a guess, never as evidence that button copy disclosed permission.

The `/inspect.html` follow-through accepts one canonical ERC-20 approval calldata layout and optionally known decimals. It labels request interpretation rather than safety or execution, renders the exact spender/raw uint256 value with text nodes, and distinguishes maximum, bounded and zero. All edits invalidate old output. Examples are explicitly invented; zero does not claim successful revocation. No network lookups, app persistence or data-bearing share URLs are used; `connect-src 'none'` and `form-action 'none'` block connections and unscripted submission. An explicit copy action contains decoded values, not a hosted public result. Unsupported layouts fail visibly, errors focus their field, success focuses the result heading, and clear removes values/output from the form. Desktop panels are adjacent; mobile panels stack and long uint256 values wrap. ABI decoding itself is established prior art, not evidence of a novel UiPath capability.

Evidence policy: local synthetic simulation is labelled throughout. The portable .flow connects manual start, an owned read-only HTTP JSON specimen, a fail-closed evaluator and end outputs. It does not inspect a UI or wallet. Strict validation and local embedded-script tests do not prove Cloud execution. Two distinct owner-controlled Cloud inputs now have verified outputs at Flow revision d85a1ddc7bb9cd1cc6a13b4d5db95474228f1fe9, with actual observation timestamps on 2026-10-06. The UX distinguishes those historical HTTP observations from browser automation and newer app features.

`/evidence.html` loads a static, deliberately redacted JSON publication; no job submission or broker. Keyboard-accessible observation buttons switch between unlimited/bounded results without more requests. The page shows the input, all eight allowlisted outputs, observed time and exact tested/public source revisions. Web Crypto computes SHA-256 over `JSON.stringify(specimen)` locally and compares it with the recorded digest. The result names a bytes match or drift, never an authenticated Cloud receipt or a safety verdict. Failure to load valid data hides observations and leaves a retry button plus raw-evidence link; JS-disabled visitors can still read the artifact. Desktop metadata/digest columns stack on mobile. Curated publication is unsigned and omits private tenant/job/operation identifiers, credentials and raw traces. Stable case-only permalinks share an observation, not user input.
