The decoded request

Nothing decoded yet. This is a request interpretation, not a signed transaction, live allowance or confirmed outcome.

This compares an unverified amount you entered with an encoded value, assuming standard ERC-20 behavior and your supplied decimals. Matching amounts do not prove honest button text, correct token units or a safe spender. A smaller request does not prove a completed purchase.

A matching selector does not prove the target is an ERC-20 token. ERC-721’s per-token approve(address,uint256) uses the same selector, but its second value is a token ID, not an allowance. Other contracts can also interpret these bytes differently. Verify the destination contract and token standard, chain and spender independently. The decoded address is lowercase, not checksum-verified.

No contract call or transaction receipt was checked. Even a bounded amount is not a safe-spender verdict. Decoding an approval does not execute or confirm a swap.

Know what is missing.

Calldata alone cannot identify the chain, token contract, sender, token decimals, existing allowance or transaction success. Permit signatures, Permit2, NFT permissions and multicalls need different inspection tools. This inspector refuses other layouts rather than guessing.
